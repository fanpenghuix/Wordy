# SM2 间隔调整设计

**日期**: 2026-06-12
**问题**: 100个词的小词库中，SM2指数增长导致部分词间隔达395天，用户总是抽到同一批词

## 问题分析

- 词库~100词，每天抽查30个（30%），工作日每天1~2遍（认读+拼写）
- 每个词平均每2~3天被抽到一次
- SM2无上限时，连续答对8次 → 间隔涨到395天 → 词"消失"
- 填充逻辑按 `next_review` 排序取最早到期的，导致同一批词每天出现
- 一天内同一词被抽2遍（认读+拼写），SM2更新2次，间隔涨得更快

## 设计方案

### 1. 最大间隔上限：5天

在 `recordResult` 中，计算完 interval 后截断：

```js
interval = Math.min(interval, 5);
```

效果：即使连续答对，任何词最多消失5天（一个工作日）。99词 ÷ 5天 ≈ 每天20个到期，池子装得下。

### 2. 同一天同一词只更新一次 SM2

在 `recordResult` 中检测 `last_review === today`，如果是当天第二次答题，先回退上一次更新的间隔变化，再以最后一次结果为准重新计算。

实现方式：
- 如果 `last_review === today`（当天已复习过），先回退到上次更新前的状态
- 然后用当前的答题结果重新计算 interval/efactor/repetitions
- 这样 SM2 按"复习天数"增长，不按"复习次数"增长

### 3. 填充时加权随机

当前 `getDueWords` 的 extraWords 按 `next_review ASC` 排序取最早到期的，导致同一批词每天出现。改为：

- 先查出所有未到期的候选词（`next_review > today`）
- 按 `1/(days_until_review)` 计算权重（越近的权重越高）
- 随机抽样（加权），每次抽到的不重复

这样今天到期的词一定会被选中（dueWords 不受影响），但5天后到期的词也有机会被提前抽到，打破"总是同一批词"的死循环。

## 影响范围

- `src/algorithms/sm2.js`: `recordResult` 函数 + `getDueWords` 函数
- 其他文件不受影响（quiz.js、stats.js 等调用接口不变）

## 验收标准

1. 任何词的 interval 不超过 5 天
2. 同一天同一词答2遍，SM2 只按最后一次结果更新
3. 连续多天抽查，抽到的词有轮换，不是同一批
